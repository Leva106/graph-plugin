# Контекст и ключевые решения

Журнал решений по проекту. Новые записи — сверху в разделе «Решения», формат: дата, решение, почему, следствия.
Если решение отменяется — не удалять, а пометить **[заменено]** и сослаться на новое.

## Контекст проекта

- **Что это:** локальный Figma-плагин (dev mode, импорт через `manifest.json`, **не публикуется**), который
  генерирует фреймы графиков из нативных слоёв Figma с цветами из дизайн-системы.
- **Сейчас:** 5 типов — line (smooth / area / stacked), bar (вертикально / горизонтально, stacked), pie / donut, scatter, radar.
  Данные — случайные («Точки: авто» по ширине) или своя таблица (вставка из Excel / Sheets, загрузка / выгрузка CSV).
- **Дальше по плану:** данные из CSV; генерация данных/графиков через подключённую LLM;
  возможная смена визуала с ECharts на другую библиотеку.
- **Дизайн-система:** токены экспортированы из Figma в `tokens/` (`Light`, `Dark`, `Default`).
  Используются группы `chart/<hue>/<tone>` (19 оттенков × 50…900) и `system/graphite/*`.
  В `Default.tokens.json` есть семантический `◊dataviz/*` — **пока не используется**.
- **Визуальный референс:** ECharts (скрин stacked area chart: Email, Union Ads, Video Ads, Direct, Search Engine).
- **UI плагина:** минимализм в духе Apple (macOS inspector).

## Ограничения среды (важно помнить)

- Sandbox Figma — урезанный JS: **нет `Intl`** (упало на `Intl.NumberFormat`), нет DOM. Код sandbox собирается в ES2017.
  Всё, что попадает в `dist/code.js`, проверять на такие API.
- `documentAccess: dynamic-page` → только async API: `getLocalVariablesAsync`, `getStyleByIdAsync`,
  `setTextStyleIdAsync`, `getNodeByIdAsync`.
- `vectorPaths` принимает только `M/L/C/Z` с числами через пробел (без запятых).
- Перед изменением текста нужно `loadFontAsync` для шрифта узла.
- Figma может держать старую сборку — после правок перезапускать плагин (или Hot reload plugin).
- Figma MCP в сессиях Claude может быть не авторизован → рендер в самой Figma проверяет пользователь.

## Решения

### 2026-09-27 — CSV-окно: изолированный черновик и валидация
- **Решение:** CSV — модальное окно (`ui/components/CsvModal.tsx`) вместо кнопок «Загрузить / Скачать»: текст текущих
  данных (разделитель по умолчанию `,`, переключатель `, ; Tab`), превью по черновику, «Копировать / Открыть… / Скачать».
  Черновик изолирован: график в плагине меняется только по «Применить» (Cmd/Ctrl+Enter), кнопка недоступна при ошибках.
  Пустое поле = ошибка → превью показывает последние корректные данные приглушённо + «Вернуть текущие данные».
- **Валидация** — `validateCsv` (`data/csv.ts`, чистая функция, покрыта тестами): ошибки (пусто, только заголовок, нет
  чисел) и предупреждения с номерами строк (число колонок, нечисловые ячейки, обрезка, особенности scatter / pie,
  пустые / повторяющиеся категории); клик по предупреждению выделяет строку. Если есть заголовок, число колонок задаёт
  он — лишние ячейки не создают «фантомную» серию.
- **Копирование:** `navigator.clipboard`, fallback `execCommand('copy')` (в iframe Figma Clipboard API может быть закрыт).
- **Защита ядра:** тест «вырожденные данные» — все типы с 0 категорий / 0 серий / только `null` без NaN / Infinity.

### 2026-09-27 — Две вкладки «Данные · Вид», editor-хук
- **Решение:** «Серии» убрана (свотч + имя — в заголовке колонки таблицы и списком под случайными данными; цвета секторов —
  «Вид → Цвета секторов»), «Текст» — сворачиваемая секция «Стили текста» в «Виде». Состояние редактора — хук
  `useChartEditor` (`ui/state.ts`), вкладки — `ui/tabs/DataTab.tsx`, `ViewTab.tsx`; `App.tsx` — шапка, сообщения, футер.
  Поповер `ColorPicker` — `position: fixed` (не обрезается скроллом таблицы).
- **Почему:** меньше переключений; настройки, которые задаются один раз (стили), не занимают место.

### 2026-09-27 — Размер: пресеты и «Вставить в фрейм»
- **Решение:** чипы `800×420 · 1200×600 · 16:9 · 4:3 · 1:1`, замок пропорций. Выделен обычный фрейм → `selection.frame`,
  чип «Как «Frame»» и кнопка «Вставить в «Frame»»: `create { parentId }` — график дочерний, по размеру родителя,
  `STRETCH/STRETCH` (в auto layout — `FILL`), тянется вместе с плейсхолдером в макете.

### 2026-09-27 — Пресеты графиков
- **Решение:** `figma.clientStorage['presets']` — `{ id, name, createdAt, spec }[]` (полная спека с данными и размером, до 50,
  общие для всех файлов). Сообщения `save-preset` / `delete-preset` → `presets { list }`, список приходит и в `init`.
  Выбор пресета загружает спеку в редактор (дальше «Создать» / «Обновить»); обновления пресета нет — удалить и сохранить заново.
  ID text styles из пресета фильтруются по текущему файлу.

### 2026-09-27 — Формат чисел и настройки осей
- **Решение:** `ChartOptions.format` (префикс, суффикс, знаки, сокращение k/M/B или тыс./млн/млрд, разделители en/ru/none) —
  `core/format.ts → formatValue` без `Intl`; применяется к оси значений и подписям значений (pie — проценты, CSV — сырые числа).
  `ChartOptions.axis` (min / max, названия осей X / Y, сетка, деления): `niceScale(…, fixed)` — ручные границы как есть,
  шаги между ними «красивые», близкий к границе шаг выкидывается; `min ≥ max` → авто + ошибка у поля. При ручных границах
  `Plot.clipsContent` (превью — `clipPath`), столбцы растут от ближайшей границы, если 0 вне диапазона. Название оси Y —
  текст, повёрнутый на 90°. Радар: только max и сетка (кольца).
- **Следствия:** новые вложенные группы опций необязательные — `migrateSpec` дополняет их дефолтами, версия спеки остаётся 3.

### 2026-09-27 — Прозрачность заливок — layer opacity
- **Решение:** полупрозрачные заливки (area линии и радара, точки scatter) — отдельные слои с `node.opacity`,
  paint с привязанной переменной — 100%. У радара полигон разделён на `Area` (заливка) и `Line` (обводка).
  В `ColorResolver.paint()` opacity возвращается на paint после `setBoundVariableForPaint`.
- **Почему:** тест в Figma: при привязке переменной paint opacity терялась — заливка всегда 100%.
  Layer opacity видна и правится в Figma («Layer»), не зависит от переменной.

### 2026-09-27 — Pie / radar скейлятся как остальные графики
- **Решение:** тело (`Pie|Donut|Radar`) — `STRETCH/STRETCH` как `Plot`; секторы, кольца, спицы, полигоны, выноски — `SCALE`;
  точки, индикаторы и подписи — в якорях 2×2 (как в декартовых графиках). Заменяет «группа CENTER» ниже.
- **Почему:** пользователь попросил однотипное поведение при ручном resize.
- **Следствия:** при непропорциональном resize круг становится овалом (с Shift — остаётся кругом); «Обновить» возвращает круг.

### 2026-09-27 — Один тип «Столбчатый» с ориентацией, ChartSpec v3
- **Решение:** тип `hbar` убран, ориентация — `options.horizontal` (вкладка «Вид» → «Ориентация»). `SPEC_VERSION = 3`;
  `migrateSpec`: `type 'hbar'` → `bar` + `horizontal: true` (графики v2 уже созданы при тесте).
  В `CartesianLayout` — поле `horizontal`. Имя фрейма: `Chart / Bar` / `Chart / Bar horizontal`.
- **Почему:** один логический график, переключение как у круговой/кольцевой.

### 2026-09-27 — «Точки: авто»
- **Решение:** `points: number | 'auto'` (по умолчанию `auto`, хранится в `source`). Дни недели → 7, месяцы → 12;
  даты и 1…N → максимум точек, при котором все подписи оси помещаются по ширине (`autoPoints`, 2…90), scatter → 30.
  При авто смена ширины перегенерирует данные с тем же seed. Кнопка «Авто» + поле (заблокировано при авто).

### 2026-09-27 — CSV: загрузка и выгрузка — **[частично заменено]** UI перенесён в CSV-окно (см. выше); парсер в силе
- **Решение:** `data/csv.ts`: RFC 4180 (кавычки, `""`, переносы в кавычках), BOM, автоопределение разделителя
  (Tab → `;` → `,`, первый, дающий одинаковое число колонок > 1; `;` раньше `,`, т.к. `,` — десятичный в RU-экспорте).
  Файл читается как UTF-8, при ошибке — Windows-1251 (Excel на RU Windows). `gridToTable` (`data/table.ts`) — общая
  с вставкой логика заголовка, лимиты 8 серий / 500 строк с предупреждением. Выгрузка — `,` и `.`, UTF-8 с BOM.
- **Где в UI:** «Загрузить CSV» — в заголовке секции «Данные» (переключает на «Таблица»), «Скачать CSV» — под таблицей.

### 2026-09-27 — Шесть типов графиков, ChartSpec v2 — **[частично заменено]** `hbar` → `bar` + `horizontal` (ChartSpec v3, см. выше)
- **Решение:** `ChartSpec.type`: `line | bar | hbar | pie | scatter | radar`, `version: 2`. Опции — один плоский
  `ChartOptions` для всех типов (при смене типа настройки не теряются). Данные серий — `(number | null)[]`, `null` = пустая ячейка.
  Scatter: `categories` = значения X (числа строками, нечисловые → 1…N). Pie: первая серия, секторы = категории,
  цвета — `categoryColors`, top-N (`maxSlices`) + «Другое».
  Stacked — опция `stack` для line (stacked area, как на референсе) и bar/hbar (положительные и отрицательные стеки раздельно).
- **Почему:** «5 самых популярных» + референс ECharts; hbar отдельным типом, чтобы в UI был один выбор без переключателя.
- **Следствия:** `shared/migrate.ts` поднимает v1 из `pluginData` (дополняет опции дефолтами) — вызывается в `code.ts`.
  Геометрия разбита на `core/layout/{common,axis,cartesian,pie,radar}.ts`, общий вход `computeLayout`
  возвращает union по `type`. Рендер: `figma/render.ts` (фрейм, заголовок, легенда) + `cartesian.ts` / `polar.ts`;
  превью — `ui/components/preview/*`. Подписи задаются `TextMark` (точка + якорь ax/ay), оба рендерера ставят их одинаково.

### 2026-09-27 — Прореживание подписей по размеру (данных больше, чем подписей)
- **Решение:** рисуются все точки, а подписи оси категорий — каждая k-я, `k = ceil((макс. ширина подписи + 12) / шаг)`,
  как `axisLabel.interval: 'auto'` в ECharts. Ширина текста оценивается без DOM (`core/text.ts`). Число делений оси
  значений зависит от длины оси (`splitDensity`, не больше `splitNumber`). На плотной линии маркеры точек рисуются
  только в подписанных категориях; значения/подписи отбрасываются при пересечении (`dropOverlapping`).
- **Почему:** на 30 дней при ширине 400px подписи слипаются; пользователь задаёт W×H до создания (поле перенесено на
  вкладку «Данные» с подсказкой «Подписей по оси: N из M»).
- **Следствия:** оценка ширины приблизительная (реальные шрифты — в Figma); при ручном resize прореживание
  не пересчитывается — «Обновить».

### 2026-09-27 — Свои данные: таблица в UI
- **Решение:** источник `{ kind: 'table' }`; редактируемая сетка (`ui/components/DataTable.tsx`) поверх чистых функций
  `data/table.ts`. Вставка блока из Excel / Sheets (TSV, `;`) в любую ячейку расширяет таблицу; строка без чисел
  сверху — названия серий. Числа: пробелы — разделители тысяч, `,` — десятичная (`parseNumber`). До 8 серий, 500 строк.
- **Почему:** пользователь выбрал таблицу (без отдельного поля для текста); вставка диапазона — стандартное поведение таблиц.
- **Следствия:** при переключении «Случайные → Таблица» текущие данные становятся стартовыми.

### 2026-09-27 — Pie / radar: нативные дуги и группа CENTER — **[заменено]** группа теперь скейлится (см. выше); дуги `arcData` и «Другое» — в силе
- **Решение:** секторы — `ELLIPSE` с `arcData` (donut через `innerRadius`), обводка цветом фона. Pie и radar лежат в группе
  размера тела графика с constraints `CENTER/CENTER`. «Другое» — нейтральный `system/graphite/400`
  (`ColorRef.hue = 'graphite'` → `system/graphite/*`, в палитре `chart/*` серого нет).
- **Почему:** SCALE превратил бы круг в овал при ручном resize.

### 2026-09-25 — Пересборка графика хранится в pluginData
- **Решение:** полная `ChartSpec` (вместе с данными и `source` — параметрами генерации) пишется в
  `frame.setPluginData('chartSpec')`. При выделении фрейма (или слоя внутри) UI восстанавливает все контролы.
  «Обновить» очищает детей и рисует **в тот же фрейм**; «Создать новый» — новый фрейм.
- **Почему:** сохраняются id, позиция, имя, комментарии и прототип-связи; данные не «перегенерируются» случайно.
- **Следствия:** `ChartSpec.version` для будущих миграций. Данные в UI — состояние, а не производная от seed:
  меняются только по «Сгенерировать» или смене параметров. Выбор того же графика повторно синхронизирует только размер.

### 2026-09-25 — Адаптивность через constraints, а не auto layout
- **Решение:** `Plot` — STRETCH, векторы — SCALE, точки/подписи — в якорных фреймах 2×2 (SCALE) с содержимым CENTER.
  Оси — полосы, прибитые к краям; заголовок и легенда — CENTER.
- **Почему:** график можно тянуть руками без плагина; круги и текст не искажаются, толщина линий не растёт.
- **Следствия:** шаг делений Y при ручном resize не пересчитывается — для этого «Обновить» (берёт текущий размер фрейма).

### 2026-09-25 — UI: превью закреплено сверху, настройки во вкладках — **[вкладки заменены]** «Данные · Вид» (см. выше)
- **Решение:** превью + Segmented-вкладки (Данные · Серии · Вид · Текст) не прокручиваются, скроллится только контент.
- **Почему:** график должен быть виден во время настройки.

### 2026-09-25 — Своё форматирование чисел
- **Решение:** `formatNumber` в `core/scale.ts` реализован вручную (разделитель тысяч `,`).
- **Почему:** в sandbox нет `Intl`.

### 2026-09-24 — Цвета: локальные variables, поиск в три шага
- **Решение:** VariableID из экспорта → точное имя (`chart/indigo/500`) → имя без верхней группы (`indigo/500`);
  не нашлось — hex из `tokens.generated.ts` + предупреждение пользователю.
- **Почему:** пользователь работает с переменными в том же файле; имена/коллекции могут отличаться от экспорта.
- **Следствия:** режим Light/Dark не навязывается — фрейм наследует режим. Прозрачность area задаётся
  `paint.opacity` поверх привязанной переменной.

### 2026-09-24 — Текст: локальные text styles с выбором в UI
- **Решение:** три стиля (заголовок / оси / легенда) выбираются из локальных text styles, дефолт — эвристика
  по размеру и названию, выбор хранится в `figma.clientStorage`. Нет стилей — Inter (Semi Bold 16 / Regular 12).

### 2026-09-24 — Разделение ChartSpec / ThemeSpec / core
- **Решение:** данные и опции — `ChartSpec` (близок к echarts `option`); визуал — `ThemeSpec` с именами токенов;
  геометрия — чистые функции `core/` без Figma API.
- **Почему:** CSV/LLM добавляются как новые источники ChartSpec; смена визуала — новый ThemeSpec;
  превью и Figma рисуют одно и то же.

### 2026-09-24 — Стек
- **Решение:** TypeScript + Preact + esbuild; UI инлайнится в один `dist/ui.html`.
- **Почему:** лёгкая сборка, удобно развивать UI (таблица данных, CSV, чат с LLM).

### 2026-09-24 — Объём MVP — **[частично заменено]** типы, stacked и данные: см. записи 2026-09-27
- Оси: X категориальная + одна Y (не dual axis). Серии: smooth и area (stacked пока нет).
- Данные: только случайная генерация (seed, диапазон, пресеты категорий).
- Цвета серий: порядок палитры как у ECharts (indigo, grass, yellow, tomato, navy, jade, mandarine, violet, pink…),
  тон 500, ручной выбор hue × тон (300–700) на серию.
- Smooth — порт алгоритма ECharts (`smooth: 0.5`, контрольные точки зажаты между соседями → без выбросов).
- Шкала Y — nice-scale ECharts (`splitNumber = 5`, всегда включает 0).
